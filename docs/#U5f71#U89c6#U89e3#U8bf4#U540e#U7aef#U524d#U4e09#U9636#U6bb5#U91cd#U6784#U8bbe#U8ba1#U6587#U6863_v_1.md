# 影视解说后端前三阶段重构设计文档 v1

## 0. 当前结论

当前影视解说链路的核心问题不是单一模型或单一参数，而是流程职责混乱：第一步切片阶段已经隐含筛选，第二步证据增强阶段也可能继续筛选，第三步高光选择又再次筛选，脚本生成和视频合成阶段还可能改变片段时间。后续重构必须先明确每一阶段的职责边界。

本版本先只严格设计前三阶段：

1. **第一步：候选切片建库**  
   只负责把整片切成候选片段，不做高光筛选。

2. **第二步：证据增强与语义校正**  
   只负责理解、补充、标注、修正候选，不主动删除候选。

3. **第三步：高光选择**  
   真正根据严格度、目标时长、剧情价值、人物线索、视觉可讲性等维度选择高光。

后续解说方案、脚本生成、配音合成、视频合成先不大改，等前三步测试稳定后再继续讨论。

## 1. 总体设计原则

### 1.1 第一步负责“切全”，不是“挑优”

第一步不判断片段是否精彩，不根据目标时长压缩候选，不使用高光严格度筛选。它只负责建立候选片段池。

禁止第一步使用：

- `target_minutes` 作为删除候选依据；
- `highlight_selectivity` 作为候选生成依据；
- `final_story_score` 作为删除依据；
- 是否高光、是否精彩、是否值得解说等判断；
- 全剧剧情理解结论；
- TTS 时长、解说长度、脚本长度。

第一步允许使用：

- 字幕时间轴；
- 视频镜头边界；
- 音频静音/弱语音边界；
- 片头、片尾、前情提要、预告等结构标记；
- 低层视觉边界信息；
- 字幕连续性、时间间隔、说话密度等结构信号。

### 1.2 第二步负责“补证据”，不是“删候选”

第二步可以做片段理解、视觉补充、人物关系、情绪、动作、剧情功能标注，但不应直接删除片段。对于弱片段、重复片段、疑似片头片尾片段，应打标签或给出删除建议，而不是从候选池中静默移除。

### 1.3 第三步才是真正的高光选择

第三步才允许使用：

- `highlight_selectivity`；
- `target_minutes`；
- `narrative_strategy`；
- 剧情推进分；
- 人物线索分；
- 情绪强度分；
- 信息增量分；
- 视觉可讲性分；
- 原声价值分；
- 因果连续性分。

### 1.4 视频时间和证据时间必须分离

所有阶段必须明确区分：

- `video_start` / `video_end`：最终视频裁剪范围；
- `evidence_start` / `evidence_end`：用于字幕、视觉、剧情理解的证据范围；
- `semantic_start` / `semantic_end`：语义核心范围，可比视频范围短；
- `tts_duration`：配音时长，只影响音频处理，不允许反向修改视频裁剪范围。

后续合成阶段必须遵守：

> 视频裁剪只认 `video_start` / `video_end`，TTS 时长不允许决定视频结束时间。

## 3. 数据结构设计

### 3.1 `SceneCandidate`

用于第一步细粒度场景候选。

```python
@dataclass
class SceneCandidate:
    candidate_id: str
    candidate_type: str  # "scene"
    video_start: float
    video_end: float
    subtitle_start: float | None = None
    subtitle_end: float | None = None
    duration: float = 0.0
    subtitle_text: str = ""
    boundary_start_reason: list[str] = field(default_factory=list)
    boundary_end_reason: list[str] = field(default_factory=list)
    boundary_confidence: str = "medium"
    source_scene_ids: list[str] = field(default_factory=list)
    nonstory_tag: str | None = None
    need_semantic_review: bool = True
```

### 3.2 `DraftStoryCandidate`

用于第一步初步合并出的故事候选块。

```python
@dataclass
class DraftStoryCandidate:
    candidate_id: str
    candidate_type: str  # "draft_story"
    video_start: float
    video_end: float
    duration: float
    children: list[str]
    subtitle_text: str
    merge_reason: list[str] = field(default_factory=list)
    boundary_confidence: str = "medium"
    need_semantic_review: bool = True
```

### 3.3 `EvidenceSegment`

用于第二步证据增强后的候选片段。

```python
@dataclass
class EvidenceSegment:
    candidate_id: str
    candidate_type: str
    video_start: float
    video_end: float
    evidence_start: float | None = None
    evidence_end: float | None = None
    subtitle_text: str = ""
    visual_evidence: dict = field(default_factory=dict)
    character_trace: dict = field(default_factory=dict)
    plot_function: str = ""
    importance_level: str = "medium"
    emotion_tags: list[str] = field(default_factory=list)
    information_tags: list[str] = field(default_factory=list)
    raw_voice_suggestion: bool = False
    drop_suggestion: bool = False
    drop_reason: str = ""
    split_merge_suggestion: dict = field(default_factory=dict)
```

### 3.4 `SelectedHighlight`

用于第三步最终高光选择。

```python
@dataclass
class SelectedHighlight:
    highlight_id: str
    source_candidate_id: str
    video_start: float
    video_end: float
    evidence_start: float | None
    evidence_end: float | None
    selected: bool
    selection_mode: str
    scores: dict
    selection_reasons: list[str]
    character_trace: dict
    keep_original_audio: bool = False
    highlight_rank: int = 0
```

## 4. 第一阶段：候选切片建库

文件：`stage1_segmentation.py`

### 4.1 阶段目标

第一阶段只做候选切片，不做高光判断。目标是：

- 覆盖正文全部可用片段；
- 边界尽量准；
- 宁可多，不可漏；
- 同时输出细粒度场景候选和粗粒度故事候选。

### 4.2 输入

```python
def build_segmentation_candidates(
    video_path: str,
    subtitle_segments: list[dict],
    *,
    segmentation_mode: str = "hybrid",  # scene / story / hybrid
    prologue_end: float | None = None,
    story_end: float | None = None,
) -> tuple[list[SceneCandidate], list[DraftStoryCandidate]]:
    ...
```

### 4.3 第一阶段准备工作

第一阶段前只做结构扫描，不做剧情理解。

准备工作包括：

1. 视频基础信息读取：
   - duration；
   - fps；
   - width / height；
   - rotation；
   - audio stream；
   - aspect ratio。

2. 字幕清洗：
   - 修复 end <= start；
   - 合并极短字幕；
   - 去除重复字幕；
   - 根据标点和停顿合并为句段；
   - 标记无字幕区间。

3. 非正文区标记：
   - 片头；
   - 前情提要；
   - 主题曲；
   - 片尾字幕；
   - 下集预告；
   - 广告；
   - 黑场。

4. 视频边界检测：
   - 镜头切换；
   - 黑场；
   - 强转场；
   - 亮度/颜色突变。

5. 音频边界检测：
   - 静音；
   - 音乐段；
   - 语音密度变化；
   - 强音效。

6. 字幕边界检测：
   - 字幕间隔；
   - 对话结束；
   - 话题转折词；
   - 说话密度变化。

### 4.4 `scene_candidates` 生成规则

`scene_candidates` 是细粒度候选，要求覆盖全片。

建议时长：

```text
最短：6–8 秒
常规：15–45 秒
最长：60–75 秒
```

规则：

- 遇到强字幕边界、强镜头边界、静音边界，优先切；
- 不切在一句话中间；
- 太短片段合并到前后；
- 太长片段按字幕停顿或镜头强边界再切；
- 无字幕动作段也要保留，标记为 `silent_action_candidate`；
- 片头片尾只标记，不静默删除。

### 4.5 `draft_story_candidates` 生成规则

`draft_story_candidates` 是初步故事块，不是最终剧情理解。

合并依据：

- 时间连续；
- 人物连续；
- 地点连续；
- 话题连续；
- 镜头连续；
- 无强转场；
- 字幕语义相近；
- 冲突或对话连续。

建议时长：

```text
常规：45–120 秒
最长：180 秒左右
```

第一阶段故事合并不能过度自信，应输出：

```python
need_semantic_review = True
merge_reason = [...]
boundary_confidence = "low" | "medium" | "high"
```

### 4.6 第一阶段输出审计

必须输出：

```text
01a_subtitle_units
01b_visual_boundaries
01c_scene_candidates
01d_draft_story_candidates
01e_coverage_report.json
```

其中 `scene_candidates` 和 `draft_story_candidates` 必须导出视频片段，方便检查是否漏切。

## 5. 第二阶段：证据增强与语义校正

文件：`stage2_evidence.py`

### 5.1 阶段目标

第二阶段不负责筛选高光，只负责理解片段、补充证据、打标签、给出拆分/合并建议。

### 5.2 输入

```python
def enrich_candidates_with_evidence(
    scene_candidates: list[SceneCandidate],
    draft_story_candidates: list[DraftStoryCandidate],
    subtitle_segments: list[dict],
    *,
    visual_model_config: dict | None = None,
    text_model_config: dict | None = None,
) -> list[EvidenceSegment]:
    ...
```

### 5.3 第二阶段要做什么

1. 片段字幕理解：
   - 片段发生了什么；
   - 谁参与；
   - 对话主题；
   - 情绪变化；
   - 人物目标变化；
   - 是否存在信息增量。

2. 视觉补充理解：
   - 人物动作；
   - 表情；
   - 场景；
   - 无字幕动作；
   - 关键视觉细节。

3. 人物线索提取：
   - 出现人物；
   - 被提及人物；
   - 主视角人物；
   - 关系变化；
   - 情绪变化；
   - 目标变化；
   - 行动动机。

4. 剧情功能标注：
   - 铺垫；
   - 发展；
   - 冲突升级；
   - 信息揭露；
   - 人物转折；
   - 关系变化；
   - 关键决定；
   - 反转；
   - 高潮；
   - 结局收束。

5. 拆分/合并建议：
   - `split`；
   - `merge_with_prev`；
   - `merge_with_next`；
   - `keep`。

### 5.4 第二阶段不能做什么

第二阶段不能主动删除候选片段。即使片段弱，也只标记：

```python
drop_suggestion = True
drop_reason = "重复寒暄 / 片头 / 无剧情 / 与前段重复"
```

真正删除或保留由第三阶段决定。

### 5.5 视觉模型使用原则

第一步只用低层视觉边界。第二步才使用视觉大模型。

抽帧策略：

- 短片段：start / middle / end；
- 长片段：每 8–12 秒抽一帧，最多 6–8 帧；
- 无字幕段：多抽；
- 情绪动作段：抽动作前后帧；
- 镜头切换后第一帧优先。

视觉输出只作为证据，不直接决定筛选。

## 6. 第三阶段：高光选择

文件：`stage3_highlight_selection.py`

### 6.1 阶段目标

第三阶段才真正根据严格度和目标时长选择高光。

### 6.2 输入

```python
def select_highlights(
    evidence_segments: list[EvidenceSegment],
    *,
    target_minutes: int,
    highlight_selectivity: str = "balanced",
    narrative_strategy: str = "mixed",
) -> list[SelectedHighlight]:
    ...
```

### 6.3 高光严格度

```text
strict：
  只选强冲突、强反转、强信息揭露、强人物转折、高潮。

balanced：
  主线关键点 + 必要铺垫 + 人物关系变化 + 情绪节点。

loose：
  大部分可讲剧情保留，只剔除重复、无效、片头片尾、明显弱段。

very_loose：
  基本保留候选，只删除广告、空白、重复废话、无效片段。
```

### 6.4 多维评分设计

第三阶段不能只靠单个 `highlight_score`。建议拆成多轨评分：

```python
scores = {
    "story_score": 0.0,
    "character_score": 0.0,
    "information_score": 0.0,
    "emotion_score": 0.0,
    "visual_score": 0.0,
    "audio_score": 0.0,
    "continuity_score": 0.0,
    "redundancy_penalty": 0.0,
}
```

综合分：

```python
highlight_score = (
    0.25 * story_score
    + 0.20 * character_score
    + 0.15 * information_score
    + 0.15 * emotion_score
    + 0.10 * visual_score
    + 0.10 * continuity_score
    + 0.05 * audio_score
    - redundancy_penalty
)
```

### 6.5 人物线索作为核心维度

人物线索是电视剧解说的重要依据，但不能作为唯一硬条件。

人物线索加分项：

- 主角出现；
- 反派布局；
- 人物目标变化；
- 人物关系变化；
- 人物心理变化；
- 人物关键行动；
- 动机暴露；
- 解释后续剧情；
- 情绪连续变化。

示例：

```json
{
  "focus_character": "男主",
  "emotion_change": "镇定 -> 紧张",
  "key_action": "掏出香烟缓解紧张",
  "motivation_hint": "害怕计划败露",
  "future_dependency": true
}
```

### 6.6 人物线索不能作为唯一标准

不应只选主角出现的片段。反派密谋、配角揭露、旁人推动主线也应进入高光候选。

规则：

```text
人物线索强 + 剧情功能强 = 必选
人物线索弱 + 信息增量强 = 可选
人物线索强 + 剧情功能弱 = loose 模式保留，strict 模式可能舍弃
```

### 6.7 高光选择输出

每个选中片段必须保留选择理由：

```json
{
  "highlight_id": "h_012",
  "source_candidate_id": "story_006",
  "video_start": 568.2,
  "video_end": 646.8,
  "selected": true,
  "selection_mode": "loose",
  "scores": {
    "story_score": 0.78,
    "character_score": 0.91,
    "emotion_score": 0.83,
    "information_score": 0.62,
    "visual_score": 0.70,
    "continuity_score": 0.88
  },
  "selection_reasons": [
    "男主目标发生变化",
    "人物关系由信任转为怀疑",
    "该片段解释后续冲突",
    "存在明显情绪压抑动作"
  ],
  "character_trace": {
    "focus_character": "男主",
    "emotion_change": "镇定 -> 紧张",
    "key_action": "掏烟缓解紧张"
  }
}
```

## 7. 审计要求

文件：`audit.py`

每一阶段都必须落盘：

```text
JSON
CSV
视频片段 clips
summary
最近 2 次运行结果
```

必须审计的阶段：

```text
01_scene_candidates
02_draft_story_candidates
03_evidence_segments
04_split_merge_suggestions
05_selected_highlights
06_rejected_candidates
```

审计重点：

- 每阶段片段数量；
- 总时长；
- 覆盖率；
- 大空窗；
- 被选中原因；
- 被拒绝原因；
- 视频片段路径；
- `video_start/video_end` 是否被缩短。

## 10. 本版本暂定结论

本版本先按以下规则写代码：

```text
第一步：切片，不筛选。
第二步：理解，不删除。
第三步：多维高光选择。
```

解说方案、混剪策略、配音和最终合成方案，先在前三步测试有效后再继续细化。
